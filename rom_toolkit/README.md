# ROM 改造工具箱

一套**跨平台、跨游戏**的老游戏 ROM 数值改造工具链。
所有套路都在「新乞丐王子（Sega Mega Drive）」上真实跑通并经过**实机验证**。

- 原文件**永远只读**，成品只往 `out/` 写
- 每步都能独立跑、独立看结果，不依赖"一次成功"
- 纯 Python，除了 `xref.py` 的反汇编需要 `capstone`，其余零依赖

---

## 一、30 秒上手：四步走

```bash
# 0) 一个解释器就够；反汇编功能另外装 capstone（见第四节）
python -m pip install capstone        # 只有 xref 的 --disasm 需要

# 1) 探壳：这是什么平台？数据压缩了吗？
python rom_probe.py <rom文件>

# 2) 定位表：用攻略里的数值序列当指纹
python find_table.py <rom文件> --seq 370,470,580,710,880

# 3) 定语义：谁在读这张表？
python xref.py <rom文件> ref 0x4043E

# 4) 打补丁：用 JSON 描述怎么改，自动 diff 校验
python patch_table.py plan.json --dry-run   # 先看效果
python patch_table.py plan.json             # 确认无误再写文件
```

**四步里最关键的是第 2 步**——只要拿到一串"表里的真实数值"，剩下的都是机械工作。

## 五、四个工具

### 1. `rom_probe.py` —— 探壳（永远第一步）

```
python rom_probe.py <rom> [--block 4096] [--no-strings] [--align-range 0x140000-0x180000]
```

输出六段：

| 段 | 内容 | 怎么用 |
|---|---|---|
| [1] 基础信息 | 大小、是否整片 Flash 容量、MD5/SHA256 | 大小是 2 的幂 → 编程器裸 dump；**MD5 拿去 Google 搜，能直接查出游戏名** |
| [2] 平台指纹 | MD / SNES / GB / GBA / NES / SMS-GG | 自动判出 CPU 和指令集 |
| [3] 熵分布图 | 每 4KB 一块的熵值条形图 | `#%@` 密集区 = 压缩或加密素材；空白区 = 没用的 Flash |
| [4] 未使用区 | 连续 0x00 / 0xFF 的大块 | 说明这后面是空的，数据只在前面 |
| [5] 对齐嗅探 | 步长 2/4/8/16/32 下各字节位为零的比例 | 某位≈100% → 填充/高位平面；某位≈50% → 4bpp 位平面图块 |
| [6] 字符串提取 | ASCII 英文语句 + 单词串 + GBK 中文串 | 调试字符串是**金矿**，常有属性名、关卡名、错误提示 |

实测（新乞丐王子）：

```
[ 95%] Sega Mega Drive / Genesis
       向量表 SSP=0x00fffffe 复位入口=0x0100  VDP($C00004) 出现 189 次
       (0x100 无 SEGA 头 → 汉化/破解/自制 ROM)
  0x300082 - 0x400000   1048446 字节  填充值 0xff
```

### 2. `find_table.py` —— 数值表指纹定位 ★核心工具

```
# 模式A：有指纹（从攻略抄来的数值序列）
python find_table.py <rom> --seq 50,152,232,370,470,580,710,880

# 模式B：没指纹，只找"单调递增的长表"
python find_table.py <rom> --monotonic --min-run 20

常用参数：--types u16be,u16le,u8,u32be,u32le   --strides 2-32
          --allow-gap 1    允许中间几个值对不上（攻略与 ROM 常有小差异）
          --min-match N    至少匹配几个才算命中
          --align 2        字段起点只接受 2 的倍数
```

它同时暴力枚举三件事，所以**你不需要预先知道表在哪**：
起始偏移 × 记录步长 × 字段宽度与字节序。

实测（18 个指纹值，0.7 秒）：

```
  匹配       编码     步长     字段起点      匹配率
  17/18    u16be  6      0x4043e      94%

最佳命中逐值对照（★=对得上，×=对不上）
  #0    50   50   ★      #8    720  920  ×   ← 中文版与英文攻略唯一不符的一格
  #1    152  152  ★      #9    1000 1000 ★
  ...
```

`--allow-gap` 就是为这种情况准备的：攻略抄错一个数、或汉化版改过数值，都不会让整次搜索失败，
而且结果会**把对不上的那一格标出来**，反而帮你发现版本差异。

### 3. `xref.py` —— 交叉引用 / 反汇编（定语义）

```
python xref.py <rom> ref   0x4043A      # 谁引用了这个地址
python xref.py <rom> dis   0xd4960 --len 0x120   # 反汇编一段
python xref.py <rom> calls 0xd1c74      # 谁调用了这个函数
python xref.py <rom> find  "20 7c 00 04 04 3a"   # 搜字节串
```

自动识别平台架构，支持 **m68k / ARM / Thumb / 6502 / 65816**。

实测：

```
查找"引用了 0x40438" 的指令
命中 3 处:
  00d2176  movea.l  #$40438, a0
  00d4990  movea.l  #$40438, a0
  00d4a10  movea.l  #$40438, a0
```

反汇编 `0xd4980` 直接把升级例程读出来了：

```
00d4982  move.b  $ff02ee.l, d0     ← 读当前等级
00d498a  add.w   d0, d0            ← ×2
00d498c  add.w   d1, d0            ← ×3
00d498e  add.w   d0, d0            ← ×6  → 等级×6
00d4990  movea.l #$40438, a0       ← 表基址
00d4996  move.w  (a0, d0.w), d3    ← 查表得"升下一级所需经验"
00d49aa  sub.w   d3, $ff02f2.l     ← 从当前经验里扣除
```

**这一步是分水岭**：光找到表只算"猜"，反汇编看到"谁在读它、读出来干什么"才算"定"。

### 4. `patch_table.py` —— 参数化补丁器

```
python patch_table.py --init plan.json          # 生成模板
python patch_table.py plan.json --dry-run       # 只看效果，不写文件
python patch_table.py plan.json                 # 真打补丁
```

`plan.json` 用 JSON 描述改什么：

```json
{
  "src": "E:/path/to/rom.bin",
  "out": "out/rom_patched.bin",
  "ops": [
    { "name": "升级所需经验",
      "base": "0x4043E", "stride": 6, "count": 28, "type": "u16be",
      "expr": "round(v / 10)", "clamp": [1, 9999] },

    { "name": "武器攻击档位，组内单调递增",
      "base": "0x3FEE2", "stride": 10, "count": 24, "type": "u16be",
      "expr": "round(v * 2 + 40)", "clamp": [1, 9999],
      "group_sizes": [4,5,4,3,4,4], "monotonic": "grow" },

    { "name": "代码里的保底立即数", "bytes": "0xD2162", "hex": "0001" }
  ]
}
```

- `expr` 里可用 `v`（当前值）、`i`（序号）和 `round/int/min/max/abs/floor/ceil/sqrt`
- `clamp` 卡上下限（**防止超出界面显示位宽**）
- `group_sizes`：分组长度表，处理"武器/角色分组"这类表
- `monotonic`：
  - `true` → 遇到数值下降就**压平**（维持在上升趋势上）
  - `"grow"` → 遇到下降就**继续爬升**（前值 + max(2, 前值×8%)）。
    这是为"原版每组最后一档是个断崖值"这类坑准备的——
    新乞丐王子里弹弓四档原本是 `30/40/50/25`，最后一档会被真正选中，
    等于**原版游戏在那里攻击力反而下降**。用 `"grow"` 就顺手把它理顺成只涨不跌
- 写完自动做**逐字节 diff**，列出所有改动区间，并校验"文件长度不变""无越界改动"

> **可信度说明**：`examples/demo_exp_only.json` 跑出来的攻击档位区，
> 与当初经**实机验证**的补丁成品逐字节完全一致（232/232 字节）。
> 也就是说这套通用描述能精确复现手写脚本的行为，不是"看起来差不多"。

## 六、实战范例：新乞丐王子（完整流程）

**背景**：用户给了一个 4MB、后缀是 `.md` 的文件，需求是"升级更容易 + 成长属性更高"。

| 步 | 动作 | 结果 |
|---|---|---|
| 1 | `rom_probe.py` | 4MiB = 32Mbit；向量表 SSP=`0x00FFFFFE`、VDP 引用 189 次 → **Sega MD**；字符串挖出 `Exceed Max fg_Item/fg_Magic`、`LEVEL/HP/MP/EXP` → **RPG + 自带调试器**；无 SEGA 头 → 汉化/破解版 |
| 2 | 问用户游戏名 | **新乞丐王子 = Beggar Prince**（台湾全崴 C&E，1996，32Mbit） |
| 3 | 联网查 GameFAQs 的 Level Up Guide | 拿到逐级经验序列 `50,152,232,370,470,580,710,880,920,1000,1240,1510,1950,2710...` |
| 4 | `find_table.py --seq ...` | **0.7 秒命中 `0x4043E`，步长 6，17/18 匹配**；唯一不符的一格说明中文版 Lv10 用 720 而非 920 |
| 5 | `xref.py ref 0x40438` | 3 处引用，反汇编确认是**升级判定例程**：读等级 → ×6 → 查表 → 扣经验 → 等级+1 |
| 6 | 进一步追 HP/MP | `$0D1C74` 算最大 HP、`$0D1CE0` 算最大 MP；字符串 xref 确认 `"HP"`→`$FF02F4`、`"MP"`→`$FF02F6` |
| 7 | 追"攻击力" | 发现**没有独立攻击属性**，攻击 = 武器分级表（`0x3FEE0`，10 字节/档，24 档）× 等级 |
| 8 | `patch_table.py` 打补丁 | 改经验列 + 攻击列，逐字节 diff 确认只动了预期位置，长度不变 |
| 9 | **实机验证** | 用户反馈"完全正确" |

**这个案例沉淀下来的通用招数：**

1. **攻略数值当指纹** —— 最省力的定位方式，前提是知道游戏名
2. **金手指码交叉验证** —— Action Replay 码 `FF1F27`（治疗术）正好等于 `$FF1F04 + 35`（第 36 个魔法），
   证明"内存布局"和"代码读的地址"对得上
3. **字符串 xref 定字段** —— `"HP"` 这个标签字符串被谁引用，谁就在显示 HP
4. **改之前先查引用范围** —— 确认目标表只被"我方计算"引用，避免连带改到敌人
5. **注意界面字段位宽** —— HP 显示区是 4 位，改到 10000 以上会串行

## 七、常见卡点与对策

| 现象 | 对策 |
|---|---|
| 不知道是什么游戏 | 把 `rom_probe.py` 的字符串段发出来人工判断；或截图标题画面；MD5 拿去搜 |
| `find_table.py` 没命中 | ①换编码 `--types u16le,u8,u32le` ②放宽步长 `--strides 2-64` ③降门槛 `--min-match 2 --allow-gap 2` ④**攻略数值可能经过换算**（显示值×10 之类），先折算再搜 |
| 表找到了，但改了没效果 | ①确认该表被代码**读**（`xref.py ref`），而不是只被别的表引用 ②可能有另一份副本（**汉化版/多版本 ROM 常有两份表**，全部都要改）③数值在写入前被重新计算覆盖 |
| 反汇编看到一堆看不懂的浮点 | 68k 用软浮点库，常量形如 `40800000=4.0`；追这些常数能识别公式（如 `1.2` = 属性克制倍率） |
| 图形渲染出来是噪声 | 图形大概率被压缩。别硬啃——**优先走数据表路线**，数值表通常不压缩 |
| 改了之后游戏崩/花屏 | 立刻换回原文件；检查是否越界写入了别的表（`patch_table.py` 的区间汇总会告诉你） |
| 中文字全是乱码 | 自定义字库（不是 GBK/Big5/SJIS）。要读文本得先把字库渲染出来重建码表，属于另一个工程量 |

## 八、安全底线

- **原文件只读**。所有工具都只从原文件读、往 `out/` 写。任何时候都能回到干净状态。
- **写前必 dry-run**，看数值对照和改动区间对不对，再真写。
- **文件长度必须不变**。改了长度（绝对地址全变）等于重写整个 ROM，风险数量级上升。
- **先小范围验证**：第一次只改一张表，进游戏看效果，确认路径通了再加第二张。
- **老存档**：只要表结构没变（改的是数值不是布局），存档通常兼容。
- 只处理**自己的设备、单机离线**的游戏；联机游戏客户端、绕过付费的一律不碰。
