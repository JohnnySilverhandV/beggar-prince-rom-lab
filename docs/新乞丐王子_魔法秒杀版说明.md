## 二、为什么改这里 —— 完整调用链

```
玩家使用魔法
   └─ 0xD4520  从已学魔法表($FF1F04)取出魔法ID → 写入 $FF038B
      └─ 0xD457C  cmpi.b #$1D,$FF038B
         │         ├─ ID < 29  → 0xD4586  jsr $0D128E   ★ 伤害魔法（29 个）
         │         └─ ID ≥ 29  → 0xD458E  jsr $0D171A   治疗/辅助（7 个）
         │
0xD128E（全部伤害魔法的【唯一】出口）
   ├─ 0xD12B8  a2 = $401FA + 魔法ID×16      ← 魔法表记录
   ├─ 0xD1328  算 MP 消耗（由 +5/+6 字段与等级推）
   ├─ 0xD1332  判定耐力 $FF038A 是否够
   ├─ 0xD133E  判定 MP $FF02F6 是否够
   ├─ 0xD13E0  遍历 6 个敌方位，数出**存活敌人数** → -$6(a6)
   ├─ 0xD1408  base = 魔法表 power(+2) 与 f4(+4)×等级² 复合
   ├─ 0xD1486  逐个敌人循环：
   │     0xD14AE  bsr $0D110C      命中判定（读魔法表 +9、怪物表 +0x13）
   │     0xD14BE  rand(4,60)+70    随机浮动
   │     0xD1526  怪物表 +0x1D     魔法抗性折减
   │     0xD155A  怪物表 +0x14/+0x17/+0x1A/+0x22  元素相性（最高 ×2.5625）
   │     0xD163A  idx = 存活敌人数 × 4
   │     0xD1640  movea.l #$3D574,a0   ← ★ 唯一引用点
   │     0xD164A  × 分摊系数
   │     0xD165C  float→int
   │     0xD1668  × 命中标志(0/1)
   │     0xD169E  sub.l d1,$FF0A14(敌HP)
   └─ 0xD16E2  循环结束
```

**这张表全 ROM 只有一条指令引用**（`0xD1640`），且位于伤害魔法专用例程 `0xD128E` 内 → 改它只影响伤害魔法。

## 三、安全性论证

**1. 不会误伤物理攻击。** 物理走 `0xD0EBE` 伤害例程，读的是武器分级表 `0x3FEE0`，与本表无关。

**2. 不会误伤敌人打我方的伤害。** 该例程只被 `0xD457C` 分支调用，是玩家施法路径。

**3. 不会误伤治疗/辅助魔法。** ID 29–35（power 字段为 0，元素码 8/9）走 `0xD171A`，不读分摊表。

**4. 溢出不发生。** 浮点→整数转换例程 `$E4DA4` 在溢出时返回 `0x80000000`（负数）——那会让"扣血"变成"加血"。按最坏情况估算：

| 场景 | base | ×200 后 |
|---|---|---|
| 最低级法术(power 150) Lv1，6 敌同屏 | ≈110 | 2.2 万 |
| 终盘法术(power 3900) Lv25，单体 | ≈7000 | 140 万 |
| 理论上限(power 4600 + f4 6×Lv40² + 元素弱点 ×2.5625) | ≈1.8 万 | **≤ 940 万** |

实测转换例程的安全区间约 2²⁴（1677 万），**上限 940 万留有余量**。

**5. 参数化可调。** 脚本 `magic_work/plan_magic_nuke.json` 里 `expr` 换成别的常数即可：
- `0x42480000`(50.0) → 温和版
- `0x42C80000`(100.0) → 中等
- `0x43480000`(200.0) → 当前（秒杀）

## 六、可选叠加 —— 魔法必中版

**成品**：`out/xqgwz_轻度_魔法秒杀必中版.bin`（MD5 `3dbc4e49db7048a36c9da02f1d95be59`）
**补丁配置**：`magic_work/plan_magic_always_hit.json`

**问题**：原版伤害魔法也要过命中率判定，放了会 miss，打起来很别扭。

**命中判定的位置**：`$0D110C` 的尾部 ——

```asm
; d4 = 命中率, d5 = rand(0,100)
00d1212  moveq  #$63, d4      ; 路径A：命中基数够高 → 固定 99
00d1214  bra.b   $d126e
00d1216  ...                  ; 路径B：按公式算（命中基数 / 敌人魔抗）
00d126c  move.w  d0, d4       ; 公式结果写回 d4
00d126e  pea.l   $64.w        ; rand(100)
00d1272  jsr     $a76d2
00d1278  move.w  d0, d5
00d127a  cmp.w   d4, d5
00d127c  bgt.b   $d1282       ; d5 > d4 → miss
00d127e  moveq   #$1, d0      ; 返回 1 = 命中
00d1282  clr.w   d0           ; 返回 0 = miss
```

**改法**：两处 d4 赋值都改成 `moveq #$7F, d4`（127），则 d4 恒为 127、`rand(0,100)` 永远不大于它 → **必定命中**。

| 地址 | 原字节 | 新字节 | 含义 |
|---|---|---|---|
| `0x0D1213` | `63` | `7F` | 路径A：99 → 127 |
| `0x0D126C`–`0x0D126D` | `38 00` | `78 7F` | 路径B：`move.w d0,d4` → `moveq #$7f,d4` |

两处**均为 2 字节等长替换**（`78 63`→`78 7F`、`38 00`→`78 7F`），不移动任何代码；实际变化 **3 字节**。

**只影响玩家施法 —— 三条证据**：

1. `$FF038B`（当前魔法 ID）全 ROM **只有 `$D4540` 一处写入**，而 `$D4540` 在玩家施法入口 `$D4500` 内，该入口从**我方队伍基址 `$FF00D2`** 取角色指针
2. `$D110C` 的目标访问的是**敌人结构数组 `$FF0A0A + idx×0x1C`**，判定方向始终是"玩家 → 敌人"
3. 敌人施法不经过 `$D4500 / $D128E / $D171A / $D110C` 这条链，敌人命中率不受影响

**副作用**：命中判定里那段"元素相性比对"（`$D1178`–`$D11F2`，原本用于折算敌人魔抗以影响命中率）在必中后成为死代码 —— 无副作用，只是不再影响结果。

**改动范围核对**：必中版 vs 秒杀版**仅 3 字节**；等级表 / 武器攻击档位 / 魔法表 / 分摊系数 / 保底经验立即数**全部逐字节一致**。
