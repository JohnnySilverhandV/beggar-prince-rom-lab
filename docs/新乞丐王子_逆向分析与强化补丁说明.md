## 二、逆向关键结论

### 2.1 升级表（本次改造的核心）

```
表基址        0x4043A
记录长度      6 字节 / 级
记录格式      [最大HP: 2字节][最大MP: 2字节][升级所需经验: 2字节]   全部大端
等级范围      1 ~ 28 级（第 28 级的经验值是封顶哨兵 9999）
表结束        0x404E1
紧邻前方      0x401FA 起是「魔法学习表」，36 条 × 16 字节，正好在 0x40439 结束
```

**游戏自己的代码读取公式**（三处互相印证）：

## 三、成品补丁

补丁方式：**原地改写，文件大小与校验位置完全不变**（该 ROM 无标准 SEGA 头、无签名、无 CRC 校验闸门，改完直接能跑）。

共 3 个强度档，按需取用：

| 文件 | 经验 | HP | MP | 说明 |
|---|---|---|---|---|
| `xqgwz_强化A_轻度.bin` | 原值 ÷10 | ×1.5+200 | ×1.5+100 | 保留成长曲线，难度降一个数量级。Lv1: 290HP/168MP；Lv28: 9650HP/4240MP |
| `xqgwz_强化B_重度.bin` | 原值 ÷50 | ×2+500 | ×2+300 | 基本一仗一级。Lv1: 620HP/390MP；Lv28: 9999HP/5820MP |
| `xqgwz_强化C_极限.bin` | 恒为 1 | 线性拉满 | 线性拉满 | **获得 1 点经验 = 升 1 级**。Lv1: 1200HP/600MP；Lv28: 9840HP/4920MP |

三个版本都同时改写了「等级 > 28 时的保底经验值 9999」（代码里的 3 处立即数），保证满级路上不会卡住。

**上限保护**：HP/MP 均限制在 9999 以内。游戏的 HP 显示字段已是 4 位宽（原版 6300 就是 4 位），超过 4 位会串行，所以不做更高。

**连续性保护**：等级 > 28 的外推公式会动态读取表尾数值作为起点（`1000×idx + 表尾HP - 27000`），所以抬高表值不会导致「升级反而掉血」。

## 四、怎么用

1. 用任意 MD 模拟器加载 `.bin`（Kega Fusion / Gens / Ares / BizHawk / RetroArch 的 Genesis Plus GX 核心均可）
2. 老存档（SRAM `.srm`）可以直接沿用，等级/经验格式没变
3. 进游戏打一场，看 HP/MP 跳变和升级提示即可确认生效

**验证小技巧**：想要更直观，可以在模拟器里开 Action Replay 码观察内存 —— `FF02EE`（等级）、`FF02F4`（HP）会直接随等级变动。

## 五、自定义

`md_analysis/patch_rom.py` 是参数化补丁器，改四个 lambda（`exp_fn` / `hp_fn` / `mp_fn` / `atk_fn`）即可生成任意强度。例如：

- 只要升级快、属性不动 → `exp_fn` 改成 `round(e/20)`，`hp_fn`/`mp_fn` 返回原值
- 只要血厚、升级速度不变 → 只改 `hp_fn`
- 想指定「升一级固定 X 点经验」 → `exp_fn` 返回常数 X
- 想指定「初始攻击力 = X」 → `atk_fn` 用 `lambda a, k: round(a * 倍率) + 常数`，让 `30×倍率 + 常数 = X` 即可
- 想只改攻击、等级表保持原版 → `patch_level=False`

## 六、攻击力（第二块改造）

### 6.1 这个游戏没有独立的「攻击力属性」

按英文资料的说法：主角只有一人（没有任何同伴/队伍），没有钱也没有商店，拿到武器/护甲自动装备。
关键的一句是 —— **「同一把武器，随着等级提升，攻击会变强，数值和画面都会变」**。
所以「成长攻击力」并不是一条属性表，而是**武器分级表 + 等级**共同决定。

代码侧完全对上了：

```
攻击档位 = $0D1D4A(武器ID, 当前等级)
    基址 = Σ $3D590[0 .. 武器ID-1]        （该武器的档位起始下标）
    然后沿着 $3FEE0 往后走，只要 $3FEE0[档位].需求等级 < 当前等级 就前进一档
    档数由 $3D590[武器ID] 封口  →  每把武器恰好占 count 档，不重不漏
结果被战斗伤害例程 $0D0EBE 使用
```

### 6.2 武器分级表结构

```
表基址     0x3FEE0        档位记录 10 字节
  +0  byte 需求等级
  +2  word ★攻击力★        ← 本次修改的字段
  +4  byte 附加
  +5  byte 属性（与怪物属性比对，相同则伤害 ×1.2）
  +6  byte 命中率（75 / 80 / 85 / 90 %）

档位计数表 0x3D590 = [0, 4, 5, 4, 3, 4, 4]  → 6 把武器、共 24 档
```

6 把武器与地点顺序完全吻合：

| 武器 | 档位数 | 原始攻击力（按需求等级） |
|---|---:|---|
| 1 弹弓 Slingshot（Shatt Town） | 4 | Lv1:30 → Lv2:40 → Lv3:50 → Lv4:25 |
| 2 长矛 Spear（Skeleton Mountain） | 5 | Lv5:120 → 140 → 180 → 200 → Lv9:85 |
| 3 战斧 Battle Axe（Vampire's Mansion） | 4 | Lv11:350 → 400 → 450 → Lv14:30 |
| 4 毒箭 Poisonous Arrow（Hulaxihu） | 3 | Lv16:800 → Lv17:880 → Lv18:60 |
| 5 宝剑 Treasured Sword（Shatt Castle） | 4 | Lv19:1300 → 1420 → 1540 → Lv22:50 |
| 6 圣杖 Holy Staff（Elven Village） | 4 | Lv24:2000 → 2200 → 2400 → Lv27:400 |

> 注意每组最后那一档（25 / 85 / 30 / 60 / 50 / 400）是**原始数据里的「断崖档」**：它在等级到点时确实会被选中，也就是说**原版游戏在这个等级段攻击力是往下掉的**。
> 本次补丁把这几档一起理顺了，保证攻击曲线只涨不跌。

### 6.3 战斗伤害例程（$0D0EBE）里确认到的机制

- 伤害例程会消耗 **耐力**：`$FF038A`，上限 100（`0x64`），每次挥击最多消耗 20
  → **满耐力正好打 5 下**，和英文评测里「physically attack your enemies up to five times」「cast one major spell per round」完全吻合
- 属性克制：武器属性（`$3FEE0+档位*10+5`）命中怪物属性（`$40C00+ID*38+7`）时伤害 ×1.2
- 命中判定在 `$0D0DF6`（用武器命中率 × 0.8 + 怪物回避 × 0.2 去比 random(0,99)）
- 伤害是浮点计算的（ROM 里带一套软浮点例程 `$E5068`~`$E5202`），常量形如 `0.8 / 0.2 / 1.2 / 1.0 / 100.0`

**安全性**：`$3FEE0` 全 ROM 只被 `$0D1D4A` 和 `$0D0EBE` 两处引用，而档位查表用的是**主角的武器槽 `$FF02EF` 和主角等级 `$FF02EE`**，所以改这张表**只会影响主角的物理攻击**，敌人伤害走另一条路（评测也印证：敌人伤害与主角等级/装备无关）。
